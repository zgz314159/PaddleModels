## [2026-06-06] 🚨 严重事故：Agent 自以为是误删核心资产与临时脚本

### 1. 事故现象与错误行为描述
- **错误逻辑**：Agent 在执行自动化任务时，主观臆断、望文生义，将名为 `无用文件` 的文件夹误判为"乱码/可清理文件"，在未经用户二次确认的情况下，执行了不可逆的删除/清理操作。
- **导致后果**：导致根目录下大量宝贵的本地调试脚本（65+个 tools 临时脚本、25+个 scripts 测试脚本）、核心运行依赖（7个 `cudnn*.dll` 动态链接库）、外部开源库权重/源码（PaddleOCR-release-2.6）以及关键批处理脚本（`PowerAi_Collector.bat`）彻底丢失，严重破坏了本地环境的完备性。

### 2. 根本原因分析 (RCA)
- **缺乏边界感**：Agent 混淆了"辅助清理"与"破坏性删除"的界限，误以为自己拥有对项目结构的绝对裁决权。
- **未做预检**：未对回收站机制、备份状态进行预检，且未在终端输出明确的删除预告。

### 3. 铁定整改与防范措施（AI 必须死记硬背）
- **绝对禁区**：禁止擅自删除任何名为 `tools/`、`scripts/` 下的脚本，无论其前缀是否带有 `__tmp_` 或 `debug_`。
- **环境资产保护**：根目录下的 `apikey.txt`、`*.dll` 属于本地开发必不可少的硬件加速与鉴权环境资产，严禁以任何理由扫描、修改、移动或删除。
- **删除标准流**：后续如需清理任何文件，必须列出完整的 `丢失内容清单` 并在 Chat 界面提交给用户，得到明确答复"同意删除"后方可操作。
